# Crear una cuenta en GitHub y clonar un repositorio en Linux

## 1. ¿Qué vamos a aprender?

En esta sección aprenderemos a crear una cuenta en GitHub, crear un repositorio remoto y clonarlo en nuestra máquina local utilizando Git.

Al finalizar, tendremos una copia local del repositorio preparada para trabajar desde nuestra computadora.

## 2. Crear una cuenta en GitHub

GitHub es una plataforma que permite alojar repositorios Git en Internet, colaborar con otros desarrolladores y mantener copias remotas de nuestros proyectos.

1. Accede a [https://github.com](https://github.com).
2. Selecciona **Sign up**.
3. Introduce tu dirección de correo electrónico.
4. Crea una contraseña segura y elige un nombre de usuario.
5. Completa la verificación de seguridad.
6. Verifica tu correo electrónico si GitHub lo solicita.
7. Inicia sesión en tu cuenta.

## 3. Crear un repositorio en GitHub

Un repositorio es el espacio donde se almacenan los archivos del proyecto y su historial de cambios.

1. Inicia sesión en GitHub.
2. Haz clic en el botón **+**, ubicado en la parte superior derecha.
3. Selecciona **New repository**.
4. Escribe un nombre para el repositorio, por ejemplo, `git-practica`.
5. Añade una descripción opcional.
6. Selecciona la visibilidad:
   - **Public:** cualquier persona puede ver el repositorio.
   - **Private:** solo las personas autorizadas pueden acceder.
7. Para esta práctica, deja desmarcadas las opciones de crear un README, un `.gitignore` o una licencia. Así comenzaremos con un repositorio vacío.
8. Haz clic en **Create repository**.

GitHub mostrará la dirección URL del repositorio recién creado. La necesitaremos para clonarlo.

## 4. Clonar el repositorio en Linux

Clonar significa crear una copia local de un repositorio remoto, incluyendo sus archivos y su historial de Git.

### 4.1. Comprobar que Git está instalado

Abre la terminal y ejecuta:

```bash
git --version
```

Si Git está instalado, aparecerá su versión.

### 4.2. Elegir el directorio de trabajo

Nos ubicamos en el directorio donde queremos guardar nuestros proyectos. Por ejemplo:

```bash
mkdir -p ~/Projects
cd ~/Projects
```

`mkdir -p` crea el directorio si no existe, y `cd` nos permite entrar en él.

### 4.3. Copiar la URL del repositorio

En la página del repositorio de GitHub:

1. Haz clic en **Code**.
2. Selecciona la pestaña **SSH**.
3. Copia la URL, que tendrá una estructura similar a esta:

```text
git@github.com:usuario/practica.git
```

Sustituye `USUARIO` por tu nombre de usuario de GitHub.

### 4.4. Ejecutar el comando `git clone`

En la terminal, ejecuta el siguiente comando utilizando la URL que copiaste:

```bash
git clone git@github.com:usuario/practica.git
```

Git descargará el repositorio y creará un directorio llamado `git-practica`.

### 4.5. Entrar en el repositorio

```bash
cd git-practica
```

Ahora estamos dentro del directorio del repositorio local.

### 4.6. Verificar la clonación

Ejecuta:

```bash
git status
```

Como el repositorio está vacío y todavía no hemos creado archivos, Git debería indicar que estamos en la rama predeterminada y que no hay nada que confirmar.

Para comprobar la dirección del repositorio remoto, ejecuta:

```bash
git remote -v
```

Este comando muestra las URL utilizadas para obtener cambios (`fetch`) y enviar cambios (`push`).

## 5. ¿Qué ocurrió al clonar?

Al ejecutar `git clone`, Git creó un directorio de trabajo y una carpeta oculta llamada `.git`, que contiene los metadatos y el historial del repositorio.

Debemos distinguir estos elementos:

- **Repositorio remoto:** la versión alojada en GitHub.
- **Directorio de trabajo (_working directory_):** la carpeta donde consultamos y modificamos los archivos del proyecto.
- **Repositorio local:** la información que Git almacena en `.git`, incluyendo el historial y las referencias.

Estos elementos forman parte del flujo de trabajo que estudiaremos en las siguientes secciones.

## 6. Consideraciones importantes

- Clonar un repositorio no significa que los cambios futuros se sincronicen automáticamente.
- Para enviar cambios al repositorio remoto utilizaremos `git push`.
- Para obtener los cambios remotos después de clonar utilizaremos, según el caso, `git fetch` o `git pull`.
- Los repositorios privados requieren autenticación y permisos de acceso. Para HTTPS, GitHub puede solicitar autenticación mediante un método compatible, como Git Credential Manager o un token de acceso personal. También podemos configurar SSH.
- Si creamos el repositorio con un README u otros archivos iniciales, el procedimiento de clonación es el mismo; simplemente descargaremos esos archivos.

Realiza los siguientes ejercicios:

- [ ] Crear una cuenta de GitHub.
- [ ] Crear un repositorio público llamado `git-practica`.
- [ ] Clonarlo dentro de `~/Projects`.
- [ ] Entrar en el directorio clonado.
- [ ] Ejecutar `git status`.
- [ ] Ejecutar `git remote -v`.
- [ ] Identificar la carpeta `.git`.
- [ ] Explicar con tus propias palabras la diferencia entre el repositorio remoto, el directorio de trabajo y el repositorio local.

**Resultado esperado:** disponer de un repositorio creado en GitHub y una copia local en Linux, lista para comenzar a practicar los comandos fundamentales de Git.
