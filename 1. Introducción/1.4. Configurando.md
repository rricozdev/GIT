# Configurando Git por primera vez

Ahora que tienes Git en tu sistema, vas a querer hacer algunas cosas para
personalizar tu entorno de Git. Es necesario hacer estas cosas solamente una vez en tu
computadora, y se mantendrán entre actualizaciones. También puedes cambiarlas en
cualquier momento volviendo a ejecutar los comandos.

Git trae una herramienta llamada `git config`, que te permite obtener y establecer
variables de configuración que controlan el aspecto y funcionamiento de Git. Estas variables pueden almacenarse en tres sitios distintos:

1. Archivo `/etc/gitconfig`: Contiene valores para todos los usuarios del sistema y todos sus repositorios. Si pasas la opción `--system` a `git config`, lee y escribe específicamente en este archivo.

2. Archivo `~/.gitconfig` o `~/.config/git/config`: Este archivo es específico de tu usuario. Puedes hacer que Git lea y escriba específicamente en este archivo pasando la opción `--global`.

3. Archivo `config` en el directorio de Git (es decir, `.git/config`) del repositorio que estés utilizando actualmente: Este archivo es específico del repositorio actual.

Cada nivel sobrescribe los valores del nivel anterior, por lo que los valores de `.git/config` tienen preferencia sobre los de `/etc/gitconfig`.

En sistemas Windows, Git busca el archivo .gitconfig en el directorio $HOME (para mucha gente será (`C:\Users\$USER`). También busca el archivo `/etc/gitconfig`, aunque esta ruta es relativa a la raíz `MSys`, que es donde decidiste instalar Git en tu sistema Windows cuando ejecutaste el instalador.

En Linux, Git busca principalmente estos archivos de configuración:

- Configuración del sistema: `/etc/gitconfig`
- Configuración global del usuario: `~/.gitconfig` (por ejemplo, `/home/usuario/.gitconfig`).
- Configuración local del repositorio: `.git/config` dentro del directorio del proyecto.

Para ver qué archivos utiliza Git:

```bash
git config --list --show-origin
```

La configuración local prevalece sobre la global, y la global sobre la del sistema, cuando varias definen la misma opción.

## Tu identidad

Lo primero que deberás hacer cuando instales Git es establecer tu nombre de usuario y dirección de correo electrónico. Esto es importante porque los "commits" de
Git usan esta información, y es introducida de manera inmutable en los commits que envías:

```bash
# estableciendo el usuario
git config --global user.name "Jhon Doe"

# configuramos el email
git config --global user.email "jhondoe@example.com"
```

Configuras tu nombre y correo una sola vez usando `--global`. Git los utilizará en todos tus proyectos.

Si quieres usar otro nombre o correo en un proyecto específico, ejecutas los mismos comandos sin `--global`, dentro de la carpeta de ese proyecto.

## Configurando el editor

En Linux, para configurar Visual Studio Code como editor predeterminado de Git, ejecuta:

```bash
git config --global core.editor "code --wait"
```

- `--global`: aplica la configuración a todos tus repositorios.

- `core.editor`: define el editor que Git utilizará.

- `code --wait`: abre VS Code y espera a que cierres el archivo antes de continuar.

Requisito: el comando code debe estar disponible en tu terminal. Puedes comprobarlo con:

```bash
code --version
```

Para verificar la configuración:

```bash
git config --global core.editor
```

## Comprobando tu Configuración

Si quieres comprobar tu configuración, puedes usar el comando `git config --list` para mostrar todas las propiedades que Git ha configurado:

```bash
git config --list

# respuesta
user.name=John Doe
user.email=johndoe@example.com
color.status=auto
color.branch=auto
color.interactive=auto
color.diff=auto
...
```

Puede que veas claves repetidas, porque Git lee la misma clave de distintos archivos
(`/etc/gitconfig` y `~/.gitconfig`, por ejemplo). En estos casos, Git usa el último valor para cada clave única que ve. También puedes comprobar el valor que Git utilizará para una clave específica ejecutando `git config <key>`:

```bash
git config user.name

# respuesta
John Doe
```

Git incluye comandos de ayuda que puedes consultar desde la terminal en cualquier momento, incluso sin conexión a Internet. Si la documentación no resuelve tus dudas, puedes recurrir a comunidades en línea, como **Stack Overflow** o los foros de GitHub, donde desarrolladores con experiencia pueden orientarte.

```bash
# listado de comandos de ayuda
git help config
```
